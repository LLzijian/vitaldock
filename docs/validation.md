# 验证记录

日期：2026-10-28。版本：0.4.0。

## 本机验证

- 环境：Windows，Python 3.12.14。
- 可选组件：官方 MCP Python SDK 1.30.0；ruff 0.17.3。
- `python -m unittest discover -s tests -v`：75 个测试通过，包含归档、实时工具和手机接口的真实 MCP stdio 子进程通信。
- `ruff check .`：通过。
- 测试数据：全部为项目内独立构造的虚构记录。

测试覆盖导出结构、单位、时间戳、人员隔离、重复数据、数值冲突、来源累积、相同时间分页、导入回滚、坏数据报告、源对象完整性、ZIP 安全边界及读取不修改数据库。MCP 测试验证工具列表、只读声明、实际查询、分页、指标范围拒绝和来源查询。

## 验收边界

实时测试验证固定主机、本人账号、GET 与鉴权格式、字段限制、认证错误脱敏、限流、最新跑步匹配、旧数据不替代新运动、每次重新请求、比较算术、恢复缺失与均值、可选查询故障和采样边界。实时 MCP 测试使用虚构客户端，在真实子进程中先返回等待，再返回刚到达的活动。

0.3 新增通用训练列表、独立 wellness、权限控制、输出截断、JSON 命令路由、无需凭据的接口发现和公开配置语法检查。发布的 `interfaces/mcp-tools.json` 与运行时工具定义逐项对照。

四个实时 MCP 工具均已通过本人账号的本地子进程只读联调；文档只记录验收范围，不包含实际健康数值、活动 ID 或凭据。跑后工具的真实跑步比较和采样序列仍需对应运动记录验收。

已按官方在线 OpenAPI 核实路径和字段，并在本人完成本机授权后验证个人 API 认证、真实华为活动与 wellness 读取。真实数据与密钥没有进入源代码、示例或测试。跑步比较与采样序列使用虚构响应回归，真实验收需要对应跑步记录。无自建华为应用审批或 Strava API 代理。

Windows／Linux 和 Python 3.11／3.12／3.13 的 CI 配置已加入仓库；远端实际结果以对应提交的 GitHub Actions 记录为准。核心可在不安装 MCP 的环境中运行，此时 MCP 集成测试会跳过；发布验证需要安装可选依赖，不能以跳过代替通过。

## 0.4 手机接口

安卓工作流 [40627539545](https://github.com/LLzijian/vitaldock/actions/runs/40627539545) 已通过：JDK 17、Gradle 8.11.1、SDK 36、APK 构建、3 项鉴权／窗口／来源策略测试及 lint。

Python 新测试覆盖固定本机 GET、口令不进入 URL／响应、每次重新读取、空记录、分页、来源保留、Strava 来源拒绝、错误脱敏、指标范围和真实 MCP 通信。公开 `interfaces/health-connect-mcp-tools.json` 与实际工具定义一致。

Android 17 真机已完成安装、本人在系统界面的只读授权、后台读取授权、USB 配对及系统凭据库保存。真实 stdio MCP 客户端成功调用连接检查、记录存在性检查和分页读取三个工具。当前真机查询返回空记录；已验收连接和空结果处理，后续需在源应用写入记录后验收实际观测与来源。切换应用时曾出现超时，恢复前台与 USB 转发后重新调用通过；持续后台在线不在当前保证范围。真实健康数值、口令和界面不写入本文件。
