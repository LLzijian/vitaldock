# 开发路线与验收条件

## 0.4 · Health Connect 手机端与 USB 读取（当前）

已加入独立安卓读取组件，使用官方 Health Connect 1.1.0 SDK，支持 13 类记录。手机接口只监听 127.0.0.1，通过已授权 USB 转发访问；电脑端提供只读 MCP、JSON 命令、Python 和系统凭据库配对。保留来源与分页，不把空数据填零，不跨来源相加。

按需读取与后台持续在线分别验收；当前不承诺手机后台永久在线。Wi-Fi 配对、长时间同步、设备来源选择、趋势汇总和更新签名属于后续工作。

## 0.3 · 注册教程与 agent 接口

已加入从 Intervals.icu 注册到首次调用的完整教程。新增连接检查、华为通用训练列表和独立恢复查询，与跑后上下文共同通过 MCP、JSON 命令、Python 开放；提供工具 JSON 定义、通用 MCP 配置、Codex 配置及可运行客户端示例。

## 0.2 · 按需原生 API 查询

已实现华为原生 Intervals.icu 连接器、系统凭据库入口、最新跑步识别、相近历史对照、近期恢复数据及采样序列、实时 MCP。每次调用重新读取，无新活动时明确等待上游，未调用自建华为应用或 Strava 中转。

验收分两步：虚构 HTTP 响应与真实 MCP 进程通信已测试；本人 API key 在本机配置后，再与已连接的华为账号逐项核对。后续发展为经批准的个人 OAuth 流程、可选 webhook、更多厂商。归档改进不作为日常使用的前置条件。

## 0.1 · 数据取回与 agent 读取

已交付：副本检查、JSON／文件夹／未加密 ZIP 导入、八类指标、原始 JSON 对象库、SQLite、重复导入处理、JSON 查询、人员及指标范围限制、只读 MCP、自动化测试与 CI。

第一份真实副本到位后的验收：各指标抽样对照运动健康，确认人员和时区，检查睡眠跨日及步数来源重叠，核对单位和未知类型。以本地数据完成验证；公开回归测试只使用新构造样例。

## 后续归档改进 · 华为导出兼容性

- 根据真实副本补充距离、热量单位，保留每个设备／导出版本的证据。
- 解析 HiTrack 心率、轨迹等细节；位置数据单独授权，默认不向 agent 开放。
- 完成文件清单、完整性检查、导入报告查看和未引用源对象清理。
- 大文件分块解析，扩展导出格式与时间戳覆盖。
- 明确日汇总的数据优先级与重叠处理规则后，再提供日总量和趋势。

验收：同一原始副本反复导入结果稳定；已知坏样例明确报错；新字段与 App 对照一致；不同成员和设备不会被静默合并。

## 后续 · 自建华为应用的持续同步

先在华为控制台验证个人开发者、Android／REST 和中国大陆的实际申请路径，再实现移动端桥接或 REST 接入。同步功能包括只读 OAuth、系统凭据库、分页、限流重试、撤销授权、延迟记录回查和可恢复检查点。

验收：真实授权账号端到端测试；无凭据进入日志或仓库；撤销授权后停止；重试不重复；检查点失败后可重启；返回范围符合获批及用户授权范围。

## 后续厂商与 agent 体验

逐一核实苹果、小米等平台的数据入口。安卓 Health Connect 现已有独立 USB 读取组件，新增厂商可先验证其是否实际写入手机数据库。新增厂商复用标准模型，不将其字段硬塞入华为结构。提供日摘要前，先完成对应数据完整性和汇总定义。

MCP SDK 2.x 迁移独立完成跨客户端验收。所有未来里程碑均为规划，不表示当前已实现。
